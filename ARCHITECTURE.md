# Architecture

## Runtime

One `net10.0-windows` WinExe in `src/MeetTape`, software tests and a separate xUnit v3 Avalonia Headless test host. `Program.Main` is STA: ordinary startup opens the GUI; unsupported user arguments show an error without initializing settings, capture or jobs. The exact test-only `--ui-smoke` runs an isolated desktop lifetime without configuration, capture, APIs or updates. `App` owns the classic desktop lifetime, window, FluentTheme and TrayIcon. AXAML uses compiled bindings with explicit data types. MainWindow delegates to MainViewModel; IDesktopController is the fake-service seam for UI tests. Stock Fluent controls form a light capture card and a ListBox table. Right-click/overflow select the targeted row before opening its shared menu; meeting Details bind live metadata/progress without reading document contents. No MVVM framework or extra DI container is used.

`DesktopInstance` holds a Windows-session named mutex through the ordinary desktop lifetime. A second launch signals a named auto-reset event and returns before initializing Avalonia/settings/devices/jobs; the primary posts window restoration to the UI dispatcher. Abandoned mutex ownership permits restart after a terminated process. Test-only smoke and rejected user arguments do not acquire this guard. The guard is disposed on the acquiring STA thread after desktop shutdown.

`DesktopController` owns `Mp3Recorder.Capture`, `PostRecordingWorkflow` and `ProcessingJobs`. Its semaphore serializes lifecycle transitions; synchronous device/FFmpeg/processing joins run on workers, never the UI dispatcher. Start joins local jobs/preparation before capture. Stop awaits title/trim; shutdown finalizes capture even if a background join fails. Capture Finished callbacks enqueue recovery outside the capture lock. Failed shutdown can be retried while further starts remain blocked.

`OperationNotice` carries typed severity/session context from capture, preparation and jobs. Preparation/jobs publish these notices directly. The UI polls typed DesktopSnapshot/session StageProgress/RetryProgress asynchronously once per second; it never parses TextWriter output. Full durable processing/capture state remains in existing session folders. Closing MainWindow hides it; explicit Exit and desktop shutdown requests await the controller. UI tests cover controls with fake services and Skia rendering.

`RecordingHotkey` registers the configured shortcut (default Ctrl+Shift+F9) with Windows `RegisterHotKey` and `MOD_NOREPEAT`, using Avalonia's gesture parser and Win32 key conversion. Settings reserves a replacement under a separate registration ID before configuration persistence; success swaps the active binding, failure releases the candidate. App routes `WM_HOTKEY` through Avalonia's window procedure hook to the same guarded MainViewModel toggle used by the window/tray and unregisters at Exit. Capture StateChanged events are serialized under the capture lock after both sources start and after Finished metadata callbacks complete, including finalization errors; DesktopController forwards them as RecordingChanged. MainViewModel deduplicates transitions and supplies generic status notices to `RecordingNotifications`. Windows `IUserNotification2` delivers these asynchronously with bounded display time and cancellation, without activating MeetTape. Delivery failure leaves capture and saved data unaffected; UI/tray status remains authoritative.

The first call in Program.Main is `VelopackApp.Build().SetAutoApplyOnStartup(false).Run()`, before Avalonia initialization. `AppUpdates` adapts UpdateManager/GithubSource; IAppUpdates is the update seam for headless tests. StartupReleaseNotice reads the Velopack feed with a bounded two-second wait and never downloads/applies packages. Non-installed/portable builds skip checks. MainViewModel owns the consent/download/live-capture-check/shutdown sequence and disables conflicting actions while updating. Settings / About binds the same model and provides a bounded check-only action plus the existing update flow with the settings dialog as confirmation owner. Checking has its own flag so Start/Stop remains available; Update is gated by known availability, live state and unsaved settings, and disables editor input/closing until completion. UpdateWindow returns consent only from Download and restart. After successful controller shutdown, WaitExitThenApplyUpdates schedules the exact approved full package and App closes the Avalonia lifetime normally. Download/apply failures retain data and require explicit retry; failure after shutdown requires reopening.

## Capture

App loads the original and prepared recording ICO once and switches tray/window icons from MainViewModel.IsRecording. Both assets include 16–256px sizes; icon changes occur only when the selected variant changes. The permanent executable icon remains the original asset.

```text
AudioDevices → WasapiPacketCapture → CaptureCoordinator
    → Mp3Recorder → Mp3Track → PcmTimeline → FfmpegEncoder
    → me.mp3 + them.mp3 + session.json
```

`AudioDevices` selects microphone/render endpoints. `WasapiPacketCapture` uses NAudio WASAPI clients to preserve native device positions, QPC timestamps and discontinuity flags. `CaptureCoordinator` owns the two-source lifecycle and reports failures. `Mp3Recorder` creates and finalizes the session.

Each `Mp3Track` has a bounded 100-packet queue of pooled mono samples and a streaming FFmpeg encoder. `PcmTimeline` maps device timing onto a shared 48 kHz grid, estimates rate from adjacent anchors, interpolates samples and represents gaps as silence. It does not fail on QPC/device-position anomalies: overlaps of any size append the complete packet after committed audio; invalid/future timestamps use the monotonic callback arrival time. This can shift audio and is reported, but does not interrupt capture. `CaptureCoordinator` aggregates per-track timing metrics while capturing and emits bounded live warnings; `Mp3Recorder` persists them at stop. The existing 500 ms horizon protects silence commitment; adjacent packets stream promptly. On stop, both track workers drain their pending PCM, then `Mp3Recorder` selects the later of their actual ends and the wall-clock stop frame; both tracks pad to that common frame before FFmpeg finalization. The persisted audio duration covers recovered speech beyond the wall-clock stop, without changing `endedAtUtc`. Originals are mono 96 kbps MP3; queue exhaustion or actual device/encoder/storage failures still stop capture with surviving audio retained. After recording faults, FFmpeg receives a bounded opportunity to flush accepted audio before disposal.

Capture ownership is process-local. Controller transitions cancel and join preparation/API jobs before starting capture; an unconfirmed shutdown blocks the start. An asynchronous capture failure restarts the canceled job runner after capture finalization, under the same synchronization gate as GUI job actions.

## Processing

```text
PostRecordingWorkflow → AudioTrimmer → selected shared interval
ProcessingJobs → AudioChunker → stereo chunks → ChatApiClient → ChunkStore
    → TranscriptAssembler → transcription.md
Automatic or manual Summary request → ChatApiClient → ChunkStore → summary.md
```

`PostRecordingWorkflow` coordinates UI-independent title/trim selection and cancellable FFmpeg preparation. `AudioTrimmer` combines edge activity from both tracks and writes separate derivatives for one shared interval. `AudioChunker` creates verified 48 kHz/192 kbps stereo MP3, L=Me/R=Them, with frame-based ownership and bounded context. Trimming and chunk preparation reject recordings longer than three hours.

`ProcessingJobs` runs a serial queue, persists stage/retry state and recovers eligible sessions from disk. Per-session linked cancellation tokens let Cancel processing join only the selected job; the controller also joins its selected trim preparation and clears pending naming after cancellation is saved. Existing session leases protect the persisted Canceled job state; canceled sessions remain ineligible until explicit Resume or Name / Trim. Its discovery cache stores modification time and length for completed, ineligible metadata, skipping JSON rereads until those attributes change; UI discovery remains uncached. Resume and Summary requests invalidate cached entries. Session leases exclude concurrent work on the same directory.

`ChatApiClient` sends non-streaming Chat Completions requests with base64 MP3 `input_audio`, or text-only Summary messages. Provider requests disable redirects and use a five-minute deadline, 8 MiB audio cap and 2 MiB response/Summary-input caps. Timeout, temporary connection and HTTP 408/429/5xx failures retry indefinitely with backoff capped at five minutes. Only HTTP 200 with an empty choices array and no structured error/provider block is marked for bounded transcription retry. `ProcessingJobs` reuses persisted `RetryProgress` and its backoff, pausing at the third failed attempt without resetting the budget on restart or while replaying earlier checkpoints. Transient failures accumulated for that chunk count toward this conservative budget. Other invalid responses and permanent/configuration/filesystem faults pause; Summary empty replies do not retry.

`ProcessingJobs` uses the `TranscriptAssembler` parser to validate timed text or the exact `[NO_SPEECH]` marker before accepting each checkpoint or uploading the next chunk. Rejected timed replies, including existing invalid timed checkpoints, are retained separately from successful checkpoints so Resume can retry them. `TranscriptAssembler` maps chunk timestamps to the original timeline and conservatively reconciles repeated same-source context. Only a complete checkpoint set publishes a transcript. New recordings persist enabled Automatic Summary as Pending at creation; disabled automatic mode leaves the stage Disabled. Manual requests work independently of the flag after publication and reject an existing pending/running/paused request. Both modes require the completed transcript and reuse saved results tied to its hash. Completed historical AwaitingRequest sessions remain untouched when settings change. Source labels and model timestamps remain estimates; no acoustic echo cancellation is implemented.

## Persistence

`AppDiagnostics` routes workflow transitions and original exceptions to `FileDiagnostics`, a bounded 128-entry BCL Channel consumed by a background file writer. The process logger starts after the single-instance guard and stays outside settings, session folders and replaceable installation files. JSON lines carry time, level, component/stage, type, HRESULT, HTTP status and bounded exception details; credential values and URL paths are redacted before writing. `ChatApiClient` adds stage and persisted job attempt/session/chunk context, request/response timing and size, server authority, bounded model/ID/header metadata, numeric token counts and allowlisted finish/block/error reasons. HTTP error bodies use the same 2 MiB read cap; unavailable/oversized diagnostic bodies retain the original HTTP failure classification. Error messages supply categorical reasons only, never raw text; unrecognized values and payload fields are omitted or redacted. The writer rotates five 1 MiB files, ignores storage failures, and drains for at most two seconds on exit. Safe typed error descriptions supply UI causes without exposing raw technical messages. Tests use scoped log sinks and synthetic failures.

`SessionRemoval` revalidates a confirmed session ID and direct-child path against controller-known meeting roots, rejects configuration/current prompt files and reparse points, pins ancestor directories and acquires the existing session lease. Controller transitions and ProcessingJobs.RemoveInactiveSession exclude capture, preparation and scheduler work during removal. Scheduler snapshots carry the discovered session ID, which is checked under the lease; disappeared paths are skipped, and a newer session reusing the folder name remains schedulable. Child handles close before the whole-folder move, following the existing rename ownership pattern. `WindowsRecycleBin` checks identity/state again after Shell binding and invokes ITransferSource.RecycleItem on an STA worker with the Windows Recycle Bin destination, retaining failure instead of falling back to permanent deletion. MainViewModel owns confirmation and selection refresh; DeleteRecordingWindow returns consent only from Move to Recycle Bin.

`SessionData` schema version 1 stores identity, capture/processing parameters, selected audio, stage progress, retry state and transcript hash. Unknown fields and unsupported schemas fail validation. Only the current session/checkpoint model is read. `SessionStore` creates temporary GUID-identified folders and provides exclusive `.session.lock` leases. After successful Stop or active capture finalization on Exit, DesktopController uses PostRecordingWorkflow.SetTitle to establish a readable folder from title, local start time and saved audio duration. Controller/capture/preparation references follow the returned path; the UUID remains in metadata. A destination collision retries the atomic directory move with the next numeric suffix, preserving occupied folders/files and session identity. During shutdown, a naming failure reports an error and retains the finalized source folder without blocking Exit. Finalized originals receive the read-only attribute; transformations write separate files.

Metadata is flushed to same-directory temporary files before replacement. `SessionStore` serializes metadata reads and writes within the process so Windows replacement cannot race an open discovery reader; session leases still protect operation ownership across processes. `ChunkStore` flushes successful checkpoints before job progress advances. Checkpoint reuse validates session/chunk identity, intervals and audio hashes before reuse; corrupt results pause instead of triggering re-upload. Transcript/Summary publication preserves differing existing documents and accepts identical output after an interrupted metadata update. Abandoned captures become interrupted/paused.

## Configuration

`ConfigurationBootstrap` embeds default configuration/prompts and writes first-use files through flushed no-overwrite moves at the single user-config path, `%APPDATA%\MeetTape\config.json`. Settings uses `ConfigurationStore.Save`, which returns a safe error message or success without console output. Candidate JSON and enabled prompts are validated before atomic replacement; a named mutex protects the final original-text comparison, replacement and key writes. Unchanged configuration and user prompts are retained. `PromptDocument` holds each editor's loaded path, original bytes and unsaved text. `ConfigurationStore` validates candidate prompt contents through the existing loader and checks every edited source under the settings mutex before per-file flushed replacement; new files use no-overwrite moves. Successful files advance their editing baseline even if a later write fails. Settings compares all editable fields and prompt contents when confirming an unsaved Close. `ConfigurationLoader` rejects malformed/unknown fields and invalid stage combinations. Capture startup skips prompt-file reads; processing reads each enabled prompt when needed and pauses with a stage-specific safe error if it is unavailable or empty.

After a successful Settings save, the existing controller applies the validated configuration under its lifecycle gate without stopping capture or cancelling jobs. Recorder configuration is used only on the next Start. Preparation captures its FFmpeg engine per operation, and processing captures FFmpeg per job; saved session stage/chunk/API contracts remain intact until explicit Resume updates API settings. The scheduler and session list retain previously selected meeting roots for the current app lifetime. Invalid saves leave runtime settings unchanged.

Meeting-root and prompt paths resolve against the configuration directory. FFmpeg receives its configured executable path/name. Endpoints require HTTPS, with HTTP allowed for loopback; API credentials come from named Process environment variables at request time, with User environment fallback for absent Process values. Settings masks new key entry and never reads an existing key into a control; successful saves write new keys to the Windows user environment and current process, not the configuration file. Session snapshots retain variable names, never key values; diagnostics omit raw provider bodies, user text and audio payloads.

## Distribution

Windows single-file self-contained publish includes native extraction for Avalonia/Skia/HarfBuzz. `assets/MeetTape.ico` is derived from the unchanged PNG artwork and contains 16/20/24/32/40/48/64/128/256-pixel frames. MSBuild embeds it as the Windows application icon and an Avalonia resource shared by the window/tray/dialogs; Velopack receives the same file through `--icon` for Setup/updater and install metadata. Windows smoke extracts actual PE icons at each size and compares them to the source, including the isolated installed shortcut and updated executable. tools/Build-Package.ps1 pins the .NET 10.0.12 runtime and Velopack/vpk 1.2.161. Build-only FFmpeg 9.0 archive download verifies SHA-256 before extracting ffmpeg.exe and its license into publish alongside LICENSE and THIRD-PARTY-NOTICES.txt. Explicit user FFmpeg paths retain priority. vpk pack uses permanent ID OriApps.MeetTape, win channel, StartMenuRoot and full packages; delta/portable outputs are disabled. No installer hooks delete data or change PATH/API keys. Settings/prompts and default meetings live outside the replaceable current directory.

CI retains both required job names and classifies changed paths: documentation skips builds, managed logic runs software/headless tests, and packaging/updater/native integration changes plus release-target PRs run full smoke. Unknown paths select full checks. The scheduler regression runs in isolation with two bounded diagnostic repeats after a failure; a passing repeat does not hide the initial failure. NuGet, pinned vpk and the SHA-256-verified FFmpeg archive use shared caches. Package smoke builds UpdateSmoke once and starts a separate process per mode, verifies two local versions with the real SDK/local feed and checks pending-update startup through real Main on an STA thread and the actual Avalonia lifetime. Artifacts retain test results, diagnostic logs/screenshots and one copy of each required release asset. On disposable GitHub-hosted runners only, Setup/apply/uninstall smoke verifies binaries and external data fixtures. Local smoke never registers or uninstalls MeetTape. tools/Test-Desktop.ps1 checks isolated startup/lifetime/Exit, with optional native hide/reopen checks; Settings controls run in the isolated Headless host. Release publication runs only on release-branch pushes, rejects an existing tag/release or skips superseded versions before packaging, creates one draft with Setup/full/feed and publishes it without overwriting immutable assets. Historical releases remain unchanged.
